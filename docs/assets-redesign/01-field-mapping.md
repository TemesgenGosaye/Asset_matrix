# 01 — Column-to-Field Mapping (BEFORE implementation)

Source of truth: `MSF_Fixed_Assets_Master_List_2025-26.xlsx` → sheet **Master List** (20,714 asset rows, 36 source departments). The portal's current `asset` model is at `prisma/schema.prisma:485-546`.

Legend:

- **REUSE** — an existing field carries the value today.
- **ADD** — nullable, additive Prisma field required (no equivalent).
- **DERIVE** — value can be reconstructed from existing data/relations but needs a new persisted column for fidelity/performance.
- **RAW** — original cell value must also be preserved verbatim.

## 2. Existing fields kept (no Excel column, must not be lost)

`assetid`, `assettag`, `modelid`, `specs`, `notes`, `purchaseprice`, `purchasedate`, `mobile`, `requestable`, `supplierid`, `manufacturerid`, `organizationId`, `creation_date`, `change_date`, `expectedEndOfLife`, `warrantyExpires`, `warrantyMonths`, `remark`, `externalId`, `externalSource`, plus all relations (attachments, maintenance schedules, reservations, transfers, checkouts, component checkouts, `userAssets`, audit entries, custom fields).

Notes:

- `remark` currently renders as the "Remark" column in the old table. It stays available as a legacy field (optionally mapped from Additional Data in a configurable column mapping, but not overwritten by default).
- `notes` stays for free-form notes.
- `externalId` / `externalSource` remain available for other integrations; the new import batch link is explicit via `ImportBatch`/`ImportRowResult`.

## 5. Decisions that need your review

1. **Property No storage** — reuse `serialnumber` (current "PID") and keep `assettag` as-is; do **not** drop/relax their global uniqueness. Duplicate Excel values are reported by the importer, not merged.
2. **First-review data** — there is no general field-history table; `AuditEntry` is campaign scan state only. The (1st) group therefore requires the new additive columns above (populated from the Excel on import). Rows not imported from the Excel will show blank (1st) columns, as specified.
3. **Finance No / Condition / Location 1st** — these cannot be faithfully derived from `audit_logs.details` (unstructured strings), so additive nullable columns are required.
4. **Department master** — reuse `Department`; add `DepartmentAlias` (name/code/alias) rather than adding an `aliases[]` array to the existing model, so mappings can be audited and org-scoped. No fact table for 36 legacy names is hardcoded in code.
5. **Import traceability** — extend `ImportJob` additively with `organizationId`, `fileHash`, `mode`, `options`, `finishedAt` and add `ImportRowResult` (one row per source row, raw JSON, warnings/errors/action/diff). Keep the old fields and all existing import endpoints.
6. **Rollback data** — `ImportRowResult.previousValues` (JSONB) stores pre-update snapshots for permission-gated batch rollback; nothing is deleted automatically.
